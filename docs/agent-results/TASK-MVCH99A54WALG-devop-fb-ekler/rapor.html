  2. Paket: R2_PUBLIC_HOST=<cPanel'e yazılacak değer> deploy/cpanel/build-package.sh <dev-sha> <çıktı>. linux/amd64, Docker ister. BUILD-INFO.txt → images.remotePatterns satırı kontrol edilir.
  3. Canlı DB (🟧 onay, sahip rolüyle, Linux konteynerinden): yedek → R-1 → prisma db push (accept-data-loss YOK) → db:rls-role → db:rls → apply-migrations.sh (son satır 47 files applied) → db:rls → rls:verify --require-db. Push'tan önce EvidenceReminder system_scope ile sayılır (0 beklenir).
  4. cPanel env: R2_ACCOUNT_ID, R2_ACCESS_KEY_ID, R2_SECRET_ACCESS_KEY, R2_BUCKET, R2_PUBLIC_BUCKET, R2_PUBLIC_HOST (paketteki değerle bire bir aynı). STOP → zip → START (KURULUM §9).

  • Docker Desktop kilitli (backend ~20 saattir açık, socket yanıt vermiyor). Bu makinedeki bütün ajanların konteyner işi durmuş durumda. Docker Desktop'ı yeniden başlatmak ofis sahibinin işi. Ben kendi başlatmadığım süreçlere dokunmadım.

  • Yerel PG 16, canlı Supabase PG 17. Yerel rol süper kullanıcı, canlıda sahip rolü değil. apply-migrations betiği bu farkı kendi kontrol ediyor (RELEASE_CHECKLIST §3.1 (i)–(iii)).
  • Admin oturumu Google ile değil, imzalı JWT ile açıldı. Yetki kararı yine DB'deki isPlatformAdmin'den. Sahte claim'li üye 403 aldı.
  • Bu, dev'in tamamını (176 commit) canlıya taşır, yalnız blog değil. İçinde 4 migration ve diğer modül değişiklikleri var.
