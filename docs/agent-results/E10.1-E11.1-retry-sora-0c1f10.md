# E10.1 + E11.1 — exit 129 sonrası tekrar (sora-0c1f10)

**Tarih:** 2026-09-06 · **Ajan:** sora-0c1f10 (Frontend Mühendisi) · **Branch:** `dev`

## 1. Ne yapıldı

### Önce: "exit 129" gerçekte neydi?

Görev notu "file write? file system permission? (`chmod 755`)" diyordu — **değil**.
`129 = 128 + 1 = SIGHUP`. Yani ajan süreci dosya yazamadığı için değil, **süreç
hangup sinyaliyle sonlandırıldığı** (pane/terminal kapandı) için öldü. Dizinlerin
tamamı yazılabilir durumda ve `chmod` gerekmedi:

```
$ ls -ld "src/app/[locale]/(app)/[workspace]/dashboard" scripts docs/BETA_DATA
drwxr-xr-x@  6 macbook  staff  192 Sep  6 19:28 src/app/[locale]/(app)/[workspace]/dashboard
drwxr-xr-x@  9 macbook  staff  288 Sep  6 19:15 scripts
drwxr-xr-x@  4 macbook  staff  128 Sep  6 19:11 docs/BETA_DATA
$ test -w "src/app/[locale]/(app)/[workspace]/dashboard" && echo WRITABLE
WRITABLE
$ kill -l 1
HUP
```

Pratik sonucu: **iki görevin dosya çıktısı da aslında diskteydi**; eksik olan iş
yarım kalan son adımlardı. Yeniden yazmak yerine kaldığı yerden tamamlandı.

### E10.1 — Dashboard rotası

`src/app/[locale]/(app)/[workspace]/dashboard/page.tsx` vardı ama (a) `metadata`
yoktu, (b) üç hata/erişim ekranı **sabit Türkçe string** ile yazılmıştı (CLAUDE.md
kural 8 ihlali), (c) hata durumunda ham `Error.message` kullanıcıya basılıyordu.

- `generateMetadata` eklendi: locale'e göre `title` + `description`, `next-intl`
  `getTranslations` üzerinden. KPI verisi kiracıya ait olduğu için
  `robots: { index: false, follow: false }`.
- Üç durum ekranı (`accessDenied`, `sessionError`, `loadError`) tek bir
  `DashboardNotice` bileşenine toplandı, `role="alert"` eklendi, metinler
  `t('...')`'e taşındı; 7 yeni anahtar **tr + en** iki dosyaya da eklendi.
- Ham hata mesajı artık ekrana değil yalnız sunucu loguna gidiyor.

### E11.1 — Beta tasarım ortağı listesi

Roster + CLI + doküman zaten commit'liydi (`9062ba6`); eksik olan **veritabanına
uygulanmasıydı**. `pnpm tsx scripts/beta-onboarding.ts --apply` çalıştırıldı:

bounce eder, gerçek kişiye ulaşmaz) ve script `--send`'i `.invalid` varken
reddediyor. Bu, örnek listeden daha güvenli olduğu için korundu.

## 4. Riskler

1. **RLS yerelde uygulanmıyor — `tests/rls.spec.ts` bu ortamda geçemez.** Kök neden
   bulundu: uygulamanın bağlandığı rol `fabrika` **SUPERUSER + BYPASSRLS**:
   ```
   [ { rolname: 'fabrika', rolsuper: true, rolbypassrls: true } ]
   ```
   Politika ve `withTenant` doğru (`tenant_isolation` → `"tenantId" = current_setting('app.tenant_id', true)`,
   tablolarda `FORCE ROW LEVEL SECURITY` açık), ama BYPASSRLS bunların hepsini geçersiz
   kılıyor. Yani **hiçbir yerel test kiracı izolasyonunu kanıtlamıyor**. Bu benim
   değişikliğimden önce de böyleydi (test "1 workspace" bekliyor, DB'de kaç workspace
   varsa onu görüyor). Beta kiracıları eklendiği için sayı 3 → 13'e çıktı, sonuç
   değişmedi (ikisi de ≠ 1). Testin kendisi de izole değil: mutlak sayı yerine
   "yalnız kendi kiracısının kaydını görüyor mu" diye sormalı.
2. Beta kiracıları **yerel dev DB'sinde**; production'a bir şey yazılmadı, e-posta
   gönderilmedi. Geri alma: `pnpm tsx scripts/beta-onboarding.ts --rollback --apply`.
3. `pnpm beta:onboard -- --apply` **çalışmıyor** — pnpm `--` ayıracını script'e
   aynen geçiriyor, script "Unknown flag `--`" ile duruyor. Doğrusu:
   `pnpm tsx scripts/beta-onboarding.ts --apply`.
4. Bu dosyada **paralel ajan var** (derin-0c1f10). Bir sonraki dokunan, üzerine
   yazmadan önce dosyayı yeniden okumalı; commit öncesi `git diff --cached` ile
   staged içeriğini doğrulamalı.
5. `src/app/[workspace]/dashboard/page.tsx.bak` — başarısız koşudan kalan, git'e
   girmemiş eski rota kopyası. Next.js rota üretmiyor (uzantı `.bak`), dokunmadım.
